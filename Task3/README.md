# Задание 3. Технический радар и роадмап

## Технический радар

`Будущее_2.0_техрадар.drawio`. Взял базовые кольца Adopt, Trial, Assess, Hold. Пустой кружок значит, что технология используется сейчас, закрашенный значит, что это предлагаемое изменение.

Оставил только то, что меняется в ландшафте, и легаси, от которого уходим. Новые технологии, которые давно зрелые на рынке (Kafka, Terraform), сразу ставлю в Adopt. Остальное новое сначала проверяем на пилоте в одном домене, поэтому Trial.

| № | Технология | Кольцо | Какие бизнес-сценарии поддерживает |
|---|---|---|---|
| 1 | Python | Adopt | ИИ-сервисы и ETL в доменах, независимое развитие ИИ |
| 2 | Go | Adopt | финтех-сервисы, независимое развитие финтеха |
| 3 | Java | Adopt | финтех-сервисы, независимое развитие финтеха |
| 4 | PowerBuilder | Hold | новых разработок не делаем, остается в клиниках до замены |
| 5 | Apache Camel (ESB) | Hold | новые интеграции только через Kafka, шину выводим |
| 6 | Apache Kafka | Adopt | интеграция новых финтех-сервисов и новых бизнесов без правок в DWH |
| 7 | Yandex Cloud | Trial | масштабирование под рост данных, отдельный каталог на каждый домен, меньше затрат на свое железо |
| 8 | Object Storage + Apache Iceberg | Trial | Lakehouse для data-продуктов, быстрая подготовка отчетности |
| 9 | SQL Server 2022 на ВМ в облаке | Trial | поддерживаемая версия для базы клиник, безопасность медданных |
| 10 | SQL Server 2008 | Hold | нет поддержки и обновлений безопасности, переносим |
| 11 | Terraform | Adopt | одинаковые среды для доменов, быстрое подключение нового бизнеса |
| 12 | Apache Airflow | Trial | ETL внутри домена, каждый домен сам готовит свой data-продукт |
| 13 | Dremio | Trial | отчеты по нескольким доменам сразу без общего DWH |
| 14 | Yandex DataLens | Trial | портал самообслуживания, сотрудник строит отчет сам |
| 15 | DataHub | Trial | каталог data-продуктов, новый домен сразу виден в витрине |
| 16 | Power BI | Hold | отчеты переносим в DataLens, новые не делаем |
| 17 | Обезличивание данных для аналитики | Adopt | медданные не попадают в витрину, соблюдение требований регуляторов |
| 18 | Data Mesh | Trial | независимое развитие направлений, подключение фармы и электроники как новых доменов |
| 19 | Централизованный DWH с бизнес-логикой | Hold | тормозит отчеты и подключение новых бизнесов, логику выносим в домены |

## Роадмап

`Будущее_2.0_роадмап.drawio`, диаграмма Ганта на год по месяцам. Цвет полосы показывает, на какую цель работает этап.

| Этап | Месяцы | Цель | Результат | Команда | Ресурсы |
|---|---|---|---|---|---|
| Э1. Архитектура и границы доменов | 1-2 | согласовать решение с бизнесом | архитектура согласована, у доменов есть границы и владельцы, проекты витрины запланированы | архитекторы, представители доменов | 2 архитектора, аналитик |
| Э2. Переезд в облако и перенос базы клиник | 2-5 | надежность и безопасность медицинских и финансовых данных | у каждого домена свой каталог в Yandex Cloud, база клиник переехала с SQL Server 2008 на новую версию, настроены бэкапы | инфраструктурная команда, команда клиник | 3 DevOps-инженера, DBA, бюджет на облако |
| Э3. Платформа данных | 3-6 | быстрые отчеты | работают Kafka, Lakehouse, Airflow, Dremio и каталог данных | платформенная команда | 4 data-инженера |
| Э4. Kafka вместо старой шины | 5-9 | финтех и ИИ развиваются отдельно | финтех и ИИ получают данные через Kafka, а не через DWH и ESB | команды финтеха, ИИ и клиник | по 2 разработчика в команде |
| Э5. Витрина данных | 6-12 | портал самообслуживания | домены публикуют свои данные, сотрудники сами строят отчеты, отчеты из Power BI перенесены | платформенная команда, домены | по data-инженеру в домене, 2 BI-аналитика |
| Э6. Подключение нового бизнеса | 10-12 | быстро подключать новые бизнесы | первый партнер (фарма или электроника) подключен как новый домен по готовому шаблону | архитекторы, платформенная команда | архитектор, 2 инженера |

Замену PowerBuilder и отключение старого DWH в этот год не берем. Бизнес разрешил пока оставить легаси, а на портал эти проекты не влияют.

## Обоснование этапов

**Э1.** Это промежуточная цель бизнеса. Если не договориться о доменах заранее, каждая команда сделает витрину по-своему.

**Э2.** SQL Server 2008 без обновлений безопасности, а в нем медданные. Переезд снижает риск утечек и отказов, а облако убирает расходы на свое железо и позволяет быстро добавлять ресурсы.

**Э3.** Без платформы отчеты так и будут строиться часами в одном DWH. С ней руководство получает данные быстрее и быстрее принимает решения.

**Э4.** Сейчас любой новый сервис финтеха или ИИ требует правок в DWH. Через Kafka он просто подписывается на нужные события, и продукт выходит быстрее.

**Э5.** Это финальная цель бизнеса. Сотрудники строят отчеты сами, аналитики больше не тратят время на выгрузки.

**Э6.** Фарма и электроника скоро войдут в компанию. По готовому шаблону их можно подключить без доработок в DWH и в других доменах.
